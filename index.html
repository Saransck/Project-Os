1. เกณฑ์การจัดตารางเวลา (Scheduling Criteria)

  • CPU Utilization: เปอร์เซ็นต์ที่ CPU ใช้งานจริง ไม่ว่างเปล่า (เป้าหมาย 40% - 90%)
  • Throughput: จำนวน Process ที่เสร็จสิ้นต่อหน่วยเวลา
  • Turnaround Time (TAT): เวลาตั้งแต่ส่ง Process เข้ามา ($AT$) จนประมวลผลเสร็จสิ้น ($CT$):
    $$TAT = CT - AT$$
  • Waiting Time (WT): เวลารวมที่ Process ต้องรออยู่ใน Ready Queue:
    $$WT = TAT - BT$$
  • Response Time (RT): เวลาตั้งแต่ส่ง Process เข้ามา จนถึงเริ่มได้รับการประมวลผลครั้งแรก ($ST_{first}$):
    $$RT = ST_{first} - AT$$

2. Preemptive vs Non-preemptive

การตัดสินใจจัดตารางเวลาของ CPU เกิดขึ้นได้ 4 กรณี:

  1. Process เปลี่ยนจาก Running → Waiting (เช่น ขอ I/O)
  2. Process เปลี่ยนจาก Running → Ready (เช่น ถูก Interrupt หรือหมด Time Quantum)
  3. Process เปลี่ยนจาก Waiting → Ready (เช่น I/O เสร็จสิ้น)
  4. Process จบการทำงาน (Terminates)

Non-preemptive: ตัดสินใจเฉพาะข้อ 1 และ 4 เท่านั้น เมื่อได้ CPU แล้วจะรันจนกว่าจะยอมปล่อยเอง

Preemptive: สามารถแย่ง CPU คืนได้ในข้อ 2 และ 3 ทันทีที่ Process สำคัญกว่าหรือมี Burst สั้นกว่าเข้ามา

3. Convoy Effect & SJF Optimality

Convoy Effect (ใน FCFS): เมื่อ Process งานยาว (CPU-bound) ได้เข้าทำก่อน ทำให้ Process งานสั้นๆ (I/O-bound) ต้องต่อคิวนาน ส่งผลให้ค่า Average Waiting Time พุ่งสูงมาก และ I/O devices ว่างเปล่า

SJF Is Provably Optimal: การนำงานสั้นมาทำก่อนให้ผลลัพธ์ Average Waiting Time ที่ ต่ำที่สุดในเชิงทฤษฎี เสมอ เพราะลดเวลารอของงานสั้นได้มากกว่าการเพิ่มเวลารอของงานยาว

4. MLFQ & Aging

Indefinite Blocking / Starvation: Process ความสำคัญต่ำอาจไม่ได้รันเลยหากมีงานที่มี Priority สูงเข้ามาเรื่อยๆ

Aging Solution: เพิ่มระดับ Priority ให้ Process ที่รอนานขึ้นเรื่อยๆ ตามกาลเวลา จนกลายเป็นงานสำคัญที่สุด

Multilevel Feedback Queue (MLFQ):
• Queue 0: Round Robin ($q=8$ ms)
• Queue 1: Round Robin ($q=16$ ms)
• Queue 2: FCFS
Process ใหม่เข้า Q0 หากใช้ CPU เกิน Quantum จะถูกลดระดับลงไปคิวล่าง!
